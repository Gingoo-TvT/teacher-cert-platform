# 备份与恢复手册

> 适用范围：广东技术师范大学教师能力考核平台一期本地部署。目标是保证 MySQL 业务数据、MinIO 附件/视频对象、审计与逻辑删除历史可按指定时间点恢复。

## 1. 备份对象

- MySQL：`teacher_cert` 库全量备份 + binlog 连续归档。
- MinIO：`teacher-cert` bucket 对象、版本与删除标记。
- 应用配置：`docker-compose.dev.yml`、生产 `.env`、证书/密钥等部署配置由运维加密保存，不提交仓库。
- 审计记录：`audit_log` 与 `backup_record` 只做归档和备份，不做普通管理端物理删除。

## 2. MySQL 全备

推荐每日低峰期执行一次全备，备份文件按日期保存。

```bash
docker exec tcp-mysql mysqldump -uroot -proot123 --single-transaction --routines --triggers --events --set-gtid-purged=OFF teacher_cert > backups/mysql/teacher_cert_YYYYMMDD.sql
```

校验：

```bash
grep -n "Dump completed" backups/mysql/teacher_cert_YYYYMMDD.sql
```

保留策略：每日备份保留 14 天，每周备份保留 8 周，每月备份保留 12 个月。生产环境需将备份同步到异机或对象存储。

## 3. Binlog 归档

生产 MySQL 必须开启 binlog，并保证 `server_id` 唯一。建议配置：

```ini
log_bin=mysql-bin
binlog_format=ROW
expire_logs_days=14
```

每日归档 binlog：

```bash
docker exec tcp-mysql mysqladmin -uroot -proot123 flush-logs
docker exec tcp-mysql bash -lc "ls -1 /var/lib/mysql/mysql-bin.*"
```

将最新 binlog 文件复制到 `backups/binlog/` 或异机备份目录。

## 4. MySQL 时间点恢复

恢复前先停止应用写入，只保留数据库维护连接。

1. 建临时库或恢复库：

```bash
docker exec tcp-mysql mysql -uroot -proot123 -e "CREATE DATABASE IF NOT EXISTS teacher_cert_restore DEFAULT CHARACTER SET utf8mb4;"
```

2. 恢复最近一次全备：

```bash
docker exec -i tcp-mysql mysql -uroot -proot123 teacher_cert_restore < backups/mysql/teacher_cert_YYYYMMDD.sql
```

3. 回放全备之后到目标时间点之间的 binlog：

```bash
docker exec tcp-mysql mysqlbinlog --stop-datetime="YYYY-MM-DD HH:MM:SS" /var/lib/mysql/mysql-bin.000001 | docker exec -i tcp-mysql mysql -uroot -proot123 teacher_cert_restore
```

4. 抽查关键表：`student`、`certificate`、`audit_log`、`file_object`、`backup_record`。

5. 确认无误后，在维护窗口内切换恢复库或导回目标记录。禁止在未校验前覆盖生产库。

## 5. MinIO 备份与恢复

生产 bucket 必须开启版本化，附件与视频禁止公开匿名访问。

```bash
mc alias set teacher-minio http://127.0.0.1:9000 minioadmin minioadmin123
mc version enable teacher-minio/teacher-cert
mc mirror --overwrite --preserve teacher-minio/teacher-cert backups/minio/teacher-cert
```

恢复对象：

```bash
mc mirror --overwrite --preserve backups/minio/teacher-cert teacher-minio/teacher-cert
```

恢复后需用业务接口或数据库 `file_object` 抽查对象 key 是否可生成限时预签名，确认材料、视频、导出包均可访问。

## 6. 业务逻辑删除恢复

业务表均使用 `deleted` 逻辑删除。误删优先走业务恢复或受控 SQL 更正，操作必须留痕：

- 记录恢复原因、操作人、时间、目标表与主键。
- 恢复前备份被恢复行。
- 恢复后查询 `audit_log` 确认更正动作有审计。

## 7. 备份记录

系统管理页的备份触发入口会写入 `backup_record`，用于记录人工备份或演练结果。当前一期不在应用内直接执行系统级 dump，避免 Web 进程持有数据库/对象存储运维权限；实际备份由运维命令或调度系统执行，平台保留记录、审计与手册链接。

建议记录：

- `backupType`：`mysql`、`minio`、`full`
- `scope`：年度、全库、bucket 或演练范围
- `remark`：备份文件名、binlog 范围、恢复目标时间点、校验结论
