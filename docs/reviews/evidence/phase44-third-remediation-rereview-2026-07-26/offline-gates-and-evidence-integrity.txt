4. Finding-defining static interleaving

The real 16/16 gate proves the intended normal paths, but its owner-loss test
deletes the writers key and immediately releases the transaction to commit. It
does not read through from that same transaction after owner loss or let a
second reader inspect the shared payload before beforeCommit.

Confirmed production sequence:

1. A transaction updates V1 to V2 and opens owner + P:ACTIVE.
2. The writers ZSET disappears while P:ACTIVE remains.
3. READ_ITEMS_WITH_VERSION sees ZCARD=0 and immediately replaces P:ACTIVE with
   a normal random version.
4. The same transaction calls listItems and MySQL read-your-writes returns its
   uncommitted V2.
5. PUT_IF_VERSION_UNCHANGED sees no writer and a matching normal version, so it
   stores V2 in shared Redis.
6. Another request can hit V2.
7. Only at beforeCommit does renewOrThrow discover the missing owner and force
   database rollback; afterCompletion clears the payload later.

Relevant implementation:

- DictServiceImpl.java:115-127
- DictServiceImpl.java:275-289
- DictServiceImpl.java:457-480
- DictServiceImpl.java:498-515
- DictServiceImpl.java:596-611
- Phase44CacheCommitWindowIT.java:415-447

This violates the stated invariant that uncommitted dictionary values are never
published to shared cache. It is the basis for the independent Medium finding
and CHANGES_REQUESTED verdict.
