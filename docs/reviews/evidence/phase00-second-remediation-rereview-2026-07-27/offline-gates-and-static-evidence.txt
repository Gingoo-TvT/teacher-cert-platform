五、本轮确认的新问题

M1 — gate 只在 Maven 前绑定 HEAD

- scripts/phase00_ci_gate.py:761-762 读取并验证一次 HEAD。
- scripts/phase00_ci_gate.py:790-797 结束时只复查 worktree clean，没有再次读取 HEAD。
- scripts/phase00_ci_gate.py:909-910 把开始时 HEAD 写入 manifest。
- 在 clean checkout 间切换、并发自动化或其它 clean HEAD 漂移时，Maven/XML/源码哈希
  可以来自另一个提交，而 manifest 仍声明开始时的 candidate SHA。
- 21 个离线反例没有 HEAD drift 用例。

M2 — target marker 没有绑定实际连接目标

- scripts/phase00_ci_gate.py:193-210 只检查 marker 非空、字符和秘密形态。
- scripts/phase00_ci_gate.py:1141-1146 的 verifier 只重复相同语法检查。
- 没有把 schema/mysql/redis/minio marker 与 SPRING_DATASOURCE_URL、
  SPRING_DATA_REDIS_*、MINIO_ENDPOINT/MINIO_BUCKET 交叉比较，也没有从运行环境采集
  credential-free 服务身份。
- GitHub workflow 当前硬编码的 marker 与连接变量看起来一致，但手工证据路径（本仓库无
  remote）完全依赖执行者同时正确填写两组值；错填时 gate 仍可把共享或其它目标标成隔离目标。

L1 — evidence verifier 的来源/路径边界不完整

- artifact 的 sourceSha256 在 verifier 中是可选字段；suite artifact 没有要求
  sourcePath 必须等于 spec report；spec 本身未进入 manifest 哈希。
- safe_relative_path 使用 PurePosixPath。在 Windows 上：
  - "..\escape" 不包含 POSIX ".." part；
  - "C:\outside\file.xml" 不被 PurePosixPath 视为 absolute；
  - "\\server\share\file.xml" 同样不被视为 POSIX absolute。
  与 Windows Path 拼接后可指向 evidence_dir 外。后续 exact directory coverage 会拒绝
  最终 PASS，但拒绝前已经尝试读取/哈希外部路径。复核只做了路径解析证明，没有读取外部文件。

L2 — Phase 清单把“应用上下文可启动”过早标为 [x]

- docs/phase-00-脚手架.md:81-83 明确 [x] 表示本候选门禁已经执行并通过。
- 同文档 :85-87 把“jar + 应用上下文可启动”整体标为 [x]。
- 提交材料 :62-64 明确本轮只跑 Surefire/skipTests package，两个 RANDOM_PORT IT 未运行。
- 因此 package 已证明，但最终候选应用上下文动态启动尚未证明；应拆分或暂置 [~]。

L3 — “全部参数”矩阵只覆盖当前 schema 的 24/32 项默认参数

- Phase00ParameterMatrixIT 锁定 docs/README.md §6 的 24 项。
