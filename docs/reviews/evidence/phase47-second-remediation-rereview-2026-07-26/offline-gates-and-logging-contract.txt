3. SDK lifecycle contract recheck

The exact locked MinIO 8.5.12 JAR was re-inspected with javap. Its async
getBucketLifecycle implementation consumes NoSuchLifecycleConfiguration and
returns null; the synchronous client returns that Future result unchanged.

Current production behavior matches that contract:

- cfg == null => explicit ABSENT => empty working rule list
- valid non-empty rules => preserve unrelated rules and replace the managed ID
- non-null cfg with null/empty rules => fail closed
- any actually thrown exception => fail closed before setBucketLifecycle

The previous Medium and its false-green positive test are therefore closed.

javap evidence:

  (bytecode 75..85) and after normal formatting (98..112).
- LoggingEvent stores argumentArray, getArgumentArray returns it, and
  getFormattedMessage formats the message separately through MessageFormatter.

Current helper FileMaintenanceServiceTest.assertFailureLogged:

- checks the formatted message for the category and sensitive sentinels;
- checks throwableProxy is null;
- checks only that argumentArray contains no Throwable.

It does not assert argumentArray cardinality, that its sole value is the fixed
category, or that each non-Throwable argument is free of sensitive sentinels.
Thus a future call such as a one-placeholder WARN supplied with an additional
sensitive String could keep the formatted message clean while the raw String
remains in LoggingEvent.argumentArray and the current helper still passes.

This is a test-regression-protection gap. The current production call passes
only classifyLifecycleFailure(e), so no current production leak was found.
