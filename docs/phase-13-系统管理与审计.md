# Phase 13 · 系统管理与审计/安全（M13）

> 优先级 P0 · 依赖：Phase 0(切面)、Phase 2 · 任务：T-104~T-108 · plan §十二 / §M13 / §4.4
> 目标：系统参数管理、审计日志查询、脱敏与水印统一治理、备份可恢复。**AT-12 首验。**

## 1. 范围
`sys_param` 管理（README §6 全量）、审计日志多维查询、脱敏/水印治理、备份与恢复策略。

## 2. 系统参数（贯穿全系统）
- 参数 CRUD（分组：cert/video/file/review/validate/student/global），热加载，类型与范围校验。
- 覆盖：证书序列作用域、省/校代码、视频阈值/合格线/人数/容差/复评模式/必过、文件大小、退回目标、姓名/证件校验、账号开通/默认密码、当前考核年度。
- **改参数即生效，无需改代码**（NFR 可配置性）。

## 3. 审计日志（AT-12）
- 统一通过 `@AuditLog` + 业务显式补充 old/new 状态采集。
- 覆盖：登录、查看、下载、导出、审核（初/复审/确认/退回）、修改、作废、重开。
- 查询维度：学生/批次/学院/时间/操作类型/操作人。
- **不可删除**：普通管理员无删除权；仅系统管理员且删除动作本身留痕（或仅归档不物理删）。

## 4. 安全治理
- 脱敏：`@Desensitize` 全局统一（证件号前6后4），明文需 `export:sensitive` + 留痕。
- 文件/视频访问统一鉴权（预签名+权限），禁公开链接；播放页动态水印组件化复用。
- 个人信息（姓名/证件号/出生日期/成绩/师德材料/视频）按敏感数据管理。

## 5. 备份与可恢复
- MySQL：定时全备 + binlog（支持指定时间点恢复）。
- MinIO：版本化/异地同步。
- 业务数据逻辑删除（不物理删），保留历史版本。
- 产出《备份与恢复手册》。

## 6. 接口与前端
- `CRUD /api/system/param`（`system:param:manage`）、`GET /api/audit/log`（`audit:view`，数据范围）。
- 前端：参数维护页、审计日志检索页、备份记录查看。

## 7. 验收清单（AT-12）
- [x] 所有初审/复审/退回/确认/作废/重开/导出均在 `audit_log` 留操作人/时间/意见/前后状态/IP。
- [x] 审计日志可按学生/批次/学院/时间/类型查询。
- [x] 普通管理员无法删除审计日志。
- [x] 改任一关键参数（如 `video.passLine`）后业务即时按新值执行。
- [x] 敏感字段全局脱敏；明文访问/导出鉴权且留痕。
- [x] 备份手册可操作，演练一次时间点恢复。

## 8. 测试用例
- T-AUD-1：执行一次"复审退回" → 日志含 old=待复审,new=复审退回,意见,操作人,IP。
- T-AUD-2（反例）：普通管理员删日志 → 拒。
- T-PARAM-1：改 `video.diffThreshold`=8 后，分差 10 的用例进入需复评。
- T-SEC-1（反例）：无 `export:sensitive` 导出明文证件号 → 拒。

## 9. DoD
参数管理 + 审计查询 + 脱敏水印 + 备份恢复可用；AT-12 自测通过；NFR 可配置性/审计/安全达标。

## 10. 风险
- 审计覆盖面要全（贯穿各 Phase 的写操作），建议在 Phase 0 切面基础上，每个业务 Phase 验收时把"是否留痕"列为回归项。
